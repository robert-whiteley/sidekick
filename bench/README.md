# Bench

Offline benchmarks that run the app's own models and logic on made-up data. Nothing here ships in
the app. Results are in [docs/BENCH.md](../docs/BENCH.md).

## Voices and transcription (`voice/`)

Measures who-is-speaking (no enrolment), recognising people again later, names from introductions,
descriptions of people with no name ("Waiter", "Bus driver"), keeping the owner's voice as "You",
and transcription accuracy, in quiet rooms and in noise.

**Every voice bench must score both names and descriptions** (SPEC item 3): a person counts as
shown right when the voice that is mainly them shows their name or their role. `score.mjs` prints
this as `shown` (everyone) and `roles` (people who are never named). Each person in
`dialogues.py` has a `role`; add one to every new person, and keep some people unnamed. Offline,
only the role phrases (`roleFromLines`) run; the model's reading runs on the phone, so check
descriptions there too.

| File           | What it does                                                                                               |
| -------------- | ---------------------------------------------------------------------------------------------------------- |
| `dialogues.py` | Eleven made-up scenes (1–4 people, three never named), each with a first and a later conversation.         |
| `gen.py`       | Synthesises them with TTS voices, mixes in noise (babble, pink, street at 20/10/5/0 dB) and room echo.     |
| `pipeline.py`  | Runs the app's speech pipeline (Silero VAD, Parakeet, CAM++) on each conversation, like `MicLoop.kt` does. |
| `score.mjs`    | Replays the lines through the app's voice and name logic (`src/memory`) and scores it.                     |
| `wer.py`       | Word error rate per condition, and how many spoken names were heard right.                                 |
| `fetch.sh`     | Downloads the models.                                                                                      |

Audio is regenerated by script (seed 7), never committed. About 3 GB for all 14 conditions.

```bash
bash bench/voice/fetch.sh $W/models
python -m venv $W/ttsvenv && $W/ttsvenv/bin/pip install sherpa-onnx==1.12.40 numpy scipy soundfile
python -m venv $W/venv && $W/venv/bin/pip install sherpa-onnx==2.0.2 numpy scipy soundfile jiwer
cd bench/voice
$W/ttsvenv/bin/python gen.py $W/data $W/models
$W/venv/bin/python pipeline.py $W/data $W/models base clean babble10            # the app as shipped
$W/venv/bin/python pipeline.py $W/data $W/models resplit:0.25:0.4:1.0:blocks2.0:words clean babble10
node --no-warnings score.mjs $W/data clean clean@resplit_0.25_0.4_1.0_blocks2.0_words
$W/venv/bin/python wer.py $W/data clean babble10
```

TTS needs sherpa-onnx 1.12.x: 2.x dropped the espeak frontend the voices use.

## Limits, robustness and battery (`limits/`)

Drives the installed app on a phone over adb with made-up questions, and logs time per answer,
app memory (PSS), app CPU time, battery level and temperature. Every tap and every typed key first
checks that Sidekick is the app in front; the script stops otherwise.

| File            | What it does                                                                       |
| --------------- | ---------------------------------------------------------------------------------- |
| `lib.sh`        | Shared helpers: adb reconnect, screen reading, foreground guard, PSS, CPU, battery |
| `chat-run.sh`   | Types each line of a questions file into the chat and logs each turn               |
| `long-chat.txt` | 56 made-up chat turns (a trip to a fictional town, facts to recall later)          |
| `long-input.sh` | One typed question of N characters                                                 |
| `mode-power.sh` | Power and CPU for one mode (app closed, Listen, Live camera, both) over N minutes  |
| `ui.sh`         | Prints what is on the phone's screen                                               |

```bash
export ADB=/path/to/adb OUT=/tmp/sk-limits
bash bench/limits/chat-run.sh bench/limits/long-chat.txt 2
bash bench/limits/long-input.sh 12000
bash bench/limits/mode-power.sh listen 25
```

## Answers and routing (`bench/answers/cases.ts`)

143 fixed prompts with the expected route (tool or rule, and key arguments) and, where checkable,
words the answer must or must not contain. Categories: general knowledge, arithmetic, dates,
units, short reasoning, every tool and command, near-misses that must not trigger a tool,
refusals (messaging "me") and multi-step requests.

- **Offline (the rules and the router's tool choice), any PC:**
  `BENCH_OUT=/tmp/answers.json npx jest __tests__/answers-bench-test.ts` — every case through the
  same rule order as the app (`src/engine/route-trace-logic.ts`), scored by
  `src/engine/answers-bench-logic.ts`. Scores: `pass` (right rule and arguments), `model` (the
  router gets a sensible tool list; the model decides on the phone), `router_risk` (a plain
  question would wait ~5 s or more for the router), `fail`.
- **On the phone (the model's answers and tool picks, with timings):** a dev or bench build,
  Speed test screen → "Answers bench", or by adb (needs the flag file below):
  `adb shell am start -a android.intent.action.VIEW -d "sidekick://bench?run=answers"`.
  One `[answers] {json}` line per case in logcat (`adb logcat -s ReactNativeJS`), then
  `[answers] summary`. The router only picks a tool; nothing is run, sent or saved.

## Memory recall (`bench/recall/generate.ts`)

About 5 weeks of invented memories (conversation notes, notes, photo captions) around 37 facts,
plus filler up to any size, and 50 questions with the expected answer words.

- Load: "Recall: load 100" on the Speed test screen, or
  `sidekick://bench?run=recall-load&size=1000`. Rows are marked `bench:` and get real embeddings
  (the first 1,000 filler rows; larger sets reuse those vectors).
- Ask: "Recall: ask" / `run=recall` — search rank and time for each question, then the full answer
  (off the record, actions dry). `run=recall-search` times search only.
- Remove: "Recall: remove" / `run=recall-clear` deletes every `bench:` row. Counts of the owner's
  own memories are logged before and after (`[recall] counts …`), never their content.

### adb deep links

Deep links run only when the file `bench-links` exists in the app's external files folder
(`/sdcard/Android/data/app.ondevice.sidekick/files/bench-links`), which only adb or the app can
create. Delete it afterwards.

### Bench-only tools (answers and recall)

None beyond the app, jest and adb. No extra dependencies.
