# 5. MVP choices made while building

Date: 2026-11-23

- **Camera:** `expo-camera` instead of vision-camera. The MVP only takes photos; no frame processors needed.
- **Embeddings:** EmbeddingGemma 2 (256 dims) through LiteRT-LM's `EmbeddingEngine`, so one runtime serves the LLM and the embedder.
- **Memory residency:** the embedder unloads the LLM first on phones under 6 GB RAM, and on any phone while Android reports low memory; otherwise both stay loaded (owner decision, Nov 2026: this replaced "never together on the Pixel 5", which would reload the chat model after every memory question).
- **Chip choice:** measure every working backend once and keep the fastest (ADR 4 listed a fixed order).
- **Consent mode:** "Automatic" by default: on where recording law needs everyone's agreement (EU/EEA, CH, AU, all-party US states, or unknown place), off elsewhere; region from the nearest bundled GeoNames city, else SIM/network/locale country. User can force On or Off.
- **Listening:** a native foreground service writes a journal file; JS ingests it. This keeps the mic working with the app closed and JS asleep.
- **Speech-to-text:** NVIDIA Parakeet TDT 0.6B v2 (int8, CC BY 4.0), measured on 73 LibriSpeech clips with 2 CPU threads: word error 2.9% clean / 24% degraded, vs Moonshine v2 base 7.5% / 72% and Parakeet 110M 4.6% / 49%. ~7x real time on PC.
- **Wake word model:** the standard gigaspeech KWS build; the `-mobile` build crashes sherpa-onnx 2.0.2 on any audio.
- **Speech-to-text on the Pixel 5:** Parakeet transcribes at ~0.25x real time after loading (6 s clip in 1.5 s, ~16 s clip in 3.9 s), fast enough to stay.
- **Speech detection:** Silero VAD v6.2.3 (MIT, file from snakers4/silero-vad; sherpa-onnx loads it like v5). On 9.4 min of LibriSpeech with noise, missed speech / false alarm: clean 6.7% / 0.9% (v5: 7.1 / 1.6), 10 dB 7.8 / 0.2 (v5: 8.6 / 0.3), 3 dB 9.0 / 0.1 (v5: 12.0 / 0.1); same speed. v5 had itself replaced the older Silero file (false alarms 11–29%). v6.3 scored the same but was a day old, so not taken yet. TEN VAD was rejected: its licence bans competing with Agora.
- **Kept after benchmarks:** CAM++ voiceprints (best on noisy 4 s clips, 1.7% EER), the gigaspeech wake-word model (0 false wakes in 52 min), Gemma 4 E2B (E4B is ~2x slower and too big for 4 GB; Qwen3.5-2B is only slightly better on images and worse on text without slow "thinking"), EmbeddingGemma 2 at 256 dims (67.8 vs 68.5 MTEB at 768).
- **Photo search by meaning:** the embedder is EmbeddingGemma 2 Text Vision 440M (388 MB, Apache-2.0) instead of the text-only 270M file (165 MB). Same text backbone (136 of 156 MB of the text file are byte-identical in the new one; model card: the vision encoder is a modular add-on), so it replaces the text model rather than adding a second. Every memory is re-embedded once when the embedder file changes, since ~20 MB of the text part differs. Photos get their own image vector on save/catch-up; rejected: waiting for the chat model's idle reading only (photo unsearchable for hours), a second CLIP-style model (two embedders, extra RAM).
- **Voice:** Kyutai Pocket TTS 100M (int8, CC BY 4.0) through sherpa-onnx 2.0.2, system voice as fallback. On the laptop with 2 threads it runs at 0.45x real time with ~1 s to first sound, and Parakeet transcribed all three test sentences back word for word (numbers, "Dr.", contractions). Kokoro v1.0 int8 ran at 1.5x real time (2.1x on 1 thread), slower than speech, and in sherpa-onnx 2.x it reads only lexicon words: numbers and "that's"/"what's" were silently skipped. sherpa-onnx 2.x no longer contains espeak-ng (GPL), and Pocket TTS needs no phonemizer. Phonon 31M needs its own runtime (not this pass); Smart Turn v3 needs the ONNX Runtime Java API, which the sherpa-onnx AAR doesn't expose, so end of turn is the VAD's 0.6 s silence.
- **Photos for the model:** camera photos are shrunk to 768 px and turned upright before the model sees them. The full 12 MP file reached the model as a black image, and the small one also answers in ~40 s instead of ~90 s.
- **Photo text (OCR):** PaddleOCR PP-OCRv6 small (det 9.9 MB + rec 21 MB, Apache-2.0, PaddlePaddle's own ONNX exports pinned to a commit) on every saved photo, instead of only the idle chat-model reading (~30 s per photo on a Pixel 5). On a laptop CPU (4 threads, detection at 960 px): 0.25 s for a 2-line sign, 0.5 s for a 10-line receipt, ~1 s for a 30-line boarding pass; every line of the English test images read correctly. Runtime: sherpa-onnx 2.0.2 has no API for arbitrary ONNX models, and Microsoft's `onnxruntime-android` cannot be added next to it: both ship `libonnxruntime.so` with different symbol versions (`OrtGetApiBase@VERS_1.28.2` vs `@VERS_1.28.0`), so whichever file Gradle keeps breaks the other. A ~150-line JNI bridge looks up the ONNX Runtime C API at run time and uses sherpa-onnx's copy (no extra 28 MB native library). Rejected: LiteRT exports of the same model (community conversion, fixed input sizes); waiting for the chat model only.
- **Online lookup (SPEC 8):** off by default. Wikipedia (Action API: search + intro extract in one request) and DuckDuckGo Instant Answers, both free with no key; optional user-entered SearXNG URL (JSON format) for full web results. Rejected as defaults: Brave Search API (needs an account and a credit card; free tier replaced by $5/month credit in 2026), Mojeek (paid, contact for pricing), Marginalia (public key is for testing and often rate-limited; real keys are paid), Google (no free API), public SearXNG instances (many disable JSON output; the limiter blocks bot traffic). When to look up is a fixed rule set in `src/web/lookup-logic.ts`: never for photos or questions about the user, their day or known people; always for "look it up", "latest/current/news" and who/what/when/where questions; otherwise Gemma may reply `LOOKUP` (hidden from the user) to trigger one. Only the question text is sent, with known people's names removed; Gemma's own words are never sent. 4 s timeout per source, failures fall back to the offline answer. User-Agent `SidekickApp/1.0 (<public project URL>; ...)`: since Wikimedia's 2026 limits, a User-Agent without a contact URL or email counts as unidentified (10 requests/min per IP; measured: 429 from the 11th request), with one 200/min. The URL is the public repo, nothing about the user (changed 26 Nov 2026 for research, which makes ~15 requests).
- **Model caches:** LiteRT's compiled caches (~1 GB for Gemma) live in `noBackupFilesDir/litert-cache`, not the cache dir: Android purged the cache dir past its ~38 MB quota, forcing a full recompile on every load. Caches for older model copies are pruned on load.
