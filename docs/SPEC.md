# Product spec

Sidekick is a general-purpose, fully on-device camera + audio assistant with the context of your life. Every feature is user-toggleable.

**Principle: the model understands, code computes.** Owner: "It should be dynamic and intelligent, hardcoding is brittle, unless it's always better like doing calculations etc., but that should probably be a hand-off. We want as few rules and bloat/context in the chat as possible, to maximise intelligence, speed, efficiency, battery usage." So working out what the user means (which tool, whether to look something up, whether to think harder) is the model's job, in any wording or language, never a word list; code only does exact work the model hands off with structured arguments (sums, unit conversion, calendar maths, time zones). Accuracy wins over speed: better slow than unreliable. Measured in docs/BENCH.md ("Rules vs model, thinking").

## Features (MVP unless marked later)

1. **Ask** — wake word (default "Hey Sidekick", changeable) and a big button; Android: Quick Settings tile and widget; iPhone: Siri, the Shortcuts app, the Action Button and Control Center ("Ask Sidekick", "Start voice question", "What am I looking at?"; they open the app). Voice or typed. Streaming answer, spoken and shown as text. Typed answers may use simple formatting (lists, steps, bold, small tables) when it helps; spoken ones are plain sentences. Long-press the last question to Edit it, or the last answer to Try again (only the last exchange, which is taken out of the chat and memory first); any answer can be read aloud, copied or shared. You can type or talk while Sidekick is answering: the message waits in line (shown faded; Send now, Edit or Remove until it starts) and is answered next with the whole chat. Send now (or long-press send while answering) stops the answer, keeps what it wrote (marked Stopped) and answers the new message; if the stopped question had no answer yet, both are answered together. "How Sidekick answers" (Settings → Assistant, up to 300 characters, e.g. "keep answers short, call me Rob, metric units") is followed in every answer, stays on the phone and is in the export.
2. **Capture** — one tap = photo (+ optional voice note) tagged with time, place and who was around. Later: Android default-assistant role ("ask about my screen"); iOS share-sheet screenshot.
3. **Conversations** — ambient transcription while listening is on. Automatic speaker separation from voice embeddings with **no enrolment**: the owner's voice is learned from wake-word / ask utterances, other voices are clustered. Names and descriptions come from conversation context, live: who answers to a name, who is thanked or introduced, and an on-device read of the conversation going on, which also describes unnamed people from what is said ("Waiter", "Bus driver"); name evidence adds up per voice, then the name is applied (undoable) or suggested; the user confirms or fixes. Tagged with time of day and place (offline place names). Auto-pause on silence and at user-chosen places/times. Live transcript on the main screen while listening (who said what; "Show conversation" toggle), automatic "Person N" labels, names applied from clear self-introductions (undoable), and an "Instructions only" mode for company (only the wake word or push-to-talk is heard).
4. **Consent mode** — default ON in all-party-consent jurisdictions (EU, CA, FL, IL, MD, MA, MT, NH, PA, WA, …). Detects verbal consent ("is it OK if I take notes?" → "yes"). Voices that have not consented are not stored. A visible mic indicator is always shown while listening.
5. **Memory** — everything goes into encrypted on-device memory; unlimited; instant search going back years by meaning, person, place or date. Detail questions ("what did that sign say this morning?") retrieve the moment from the vector index, then re-open the **original image** and read it with the vision model. Hybrid retrieval: embeddings + OCR text + keyword; captions only when cheap. People pages (notes, what you asked them to do, facts they mentioned — approved before use — and recent conversations). Saved facts vs inferred facts (inferred facts need approval).
6. **Follow-ups** — to-dos, events and reminders proposed from conversations, questions and captures; each waits for approve / edit / dismiss (Settings). Approved reminders fire as local notifications; optional daily digest (off by default). Never written to a calendar without confirmation. Ask "what do I need to do?".
7. **Your data sources** (later) — notes, user-picked folders (Storage Access Framework / document picker), optional contacts, calendar, location; Android: notifications. **Share in** (Android; iPhone later): PDFs, text documents and recordings shared from any app's Share menu become the chat's subject with buttons (Summarise, Action points, Transcript); long documents are read in parts; a recording is turned into text in the background with a progress bar (who said what, no enrolment) and saved to memory. **Text tools** (Android; iPhone later): Sidekick in any app's text-selection menu proofreads, rewrites (friendlier, more professional, shorter), summarises or drafts a reply; the result goes back into the app when its text is editable, else Copy / Share. **What did I miss?** (Android): a short summary of unread notifications by person and app; never sends anything.
8. **Web search** — optional online lookup (Wikipedia, DuckDuckGo instant answers, optional own SearXNG; for news, GDELT headlines, Wikipedia current events and optional user-added RSS/Atom feeds; the on-device model writes the search words), off by default; an Online/Offline button on the Ask screen switches it and shows "Offline" whenever there is no internet. When on, Sidekick decides by itself when a question needs the web. A "Search the web in your browser" link (full results, free; ADR 6) shows only when it helps: a lookup found nothing, or with lookup off, an explicit search or a news / latest question. A shared or pasted web link is read (that page only, its main text) and answered from with the page as the source; offline it waits in the online queue. Questions, research, the weather and directions asked for offline wait too (directions to a known place or town start in Maps at once, for offline maps) and run when back online, with a Cancel card; answers arrive in the chat and as a notification; directions start by themselves only if asked within 15 minutes and Sidekick is open, otherwise a tap starts them.
9. **Photo edits** (Android) — send a photo with a request ("make the background white", "blur the background", "turn it the right way up", "crop it square", "black and white", "brighten it"); the model decides whether an edit is meant and which. The result is a new copy with Share / Save (the original is untouched; unsaved copies go after 2 days). Background edits use a 4.6 MB cut-out model downloaded on first use.
10. **Interpreter** — "help me talk to this taxi driver in Spanish": a two-way spoken interpreter that works offline. The phone lies between two people; the top half faces the other person (upside down, in their language), the bottom half the owner. Each taps their own mic; Sidekick shows the translation on the other side and speaks it with the phone's own offline voice for that language. The model decides when to start, which language, and when the owner is talking to Sidekick instead ("thanks Sidekick, that's all" ends it, "use French with him" switches). English for the owner; 35 other languages (ADR 6 "Interpreter"). Nothing is kept.
11. **Data control** — export everything (JSON + media zip); delete an item, person, time range or everything; retention settings. Facts about health, religion or beliefs, sexuality, politics or money (yours or other people's) are never suggested for saving unless Settings → Privacy → Memory → "Suggest private facts" is on (off by default); the model decides in its fact pass.

## Not in scope

- Self-coding or autonomous agents.
- Any action without the user's confirmation.
- Accounts, telemetry, ads.

## Later targets

Smart glasses, a dedicated camera, laptop. Keep the engine portable.
